# Presentation evidence and limitations

This index records the basis for the introduction, not a private source
inventory or evidence that the bot passed its acceptance tests.

| Source | Supports | Limits |
|---|---|---|
| [Project README](../../README.md) and [host guide](../../host_app/README.md) | Host boundary, configuration modes, 35-manual pilot baseline | Source code and configuration presence do not prove live service operation. |
| [Bot behavior](../../Docs/bot-behavior.md), [instructions](../../Docs/bot-instructions.md), and [tests](../../Docs/bot-tests.md) | Prepared behavior, safety rules, and ten acceptance tests | Prepared requirements are not evidence of applied settings or passing results. |
| [EDAV integration guide](https://github.com/cdcent/edav-BaaS) | Documented `clientId`, JWT and message handshake | It does not establish that all integrations accept app-only tokens or operate without a token. |
| User-supplied EDAV iframe example in the project conversation | A distinct `IntegrationId` integration was supplied without a token | Specific to that integration; it does not establish a universal EDAV contract. |
| User-supplied screenshot in the project conversation | A response was displayed and the interface reported 25 documents at that moment | Not proof of source correctness, full processing, the current corpus, or acceptance-test success. |
| [MDN browsing guide](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Environment_setup/Browsing_the_web) and [Microsoft bot design](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/design/bots) | General explanations of web apps and conversational bots | Not evidence of EDAV's internal implementation. |

Confirm portal configuration, processed-source counts, reliable citations,
access arrangements and live behavior with the relevant owners before making
readiness claims. Follow the controlled acceptance tests and check answers
against the official sources. The illustration contains no real manual text.
